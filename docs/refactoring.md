# Что изменено при подготовке дипломной версии

## Удалено

Мобильный Flutter-клиент и связанная с ним часть проекта удалены. В дипломной версии остаётся web-клиент.

## Архитектура

Исходные handlers выполняли сразу несколько ролей: разбирали HTTP, выполняли SQL, управляли транзакциями и содержали бизнес-правила.

В новой версии эти обязанности разделены:

```text
Handler
  -> Service
      -> Repository interface
          -> PostgreSQL repository
```

## Основные изменения

### Auth

HTTP-обработка находится в `auth/handler.go`, бизнес-операции — в `auth/service.go`, работа с пользователями — в `auth/postgres_repository.go`.

### Masters

Проверка роли и операции профиля вынесены в Service, SQL — в Repository.

### Services

Проверка названия, цены и длительности выполняется в Service. Получение идентификатора профиля мастера также происходит через интерфейс зависимости.

### Schedule

Проверка номера дня и корректности интервала выполняется в Service, а сохранение — в Repository.

### Appointments

Это основной бизнес-сценарий проекта. Service отвечает за:

- получение длительности услуги;
- вычисление времени окончания;
- проверку рабочего времени;
- расчёт доступности;
- изменение бизнес-состояния записи.

Repository отвечает за SQL и транзакционное создание записи. Внутри транзакции строка профиля мастера блокируется `FOR UPDATE`, после чего повторно проверяется пересечение интервалов.

### Notifications

Service управляет сценарием уведомлений, а Repository отвечает за CRUD-операции PostgreSQL.

## Дополнительные улучшения

- availability учитывает длительность услуги;
- запись не может выходить за пределы рабочего интервала;
- добавлены индексы для часто используемых запросов;
- web-клиент встроен в бинарный файл Go через `go:embed`;
- добавлены unit-тесты ключевой бизнес-логики бронирования;
- добавлена документация архитектуры, ER-модели и сценария защиты.
