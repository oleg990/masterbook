# MasterBook

Веб-система для онлайн-записи клиентов к мастерам услуг.

## Технологии

- Go 1.23+
- PostgreSQL 16
- REST API
- HTML/CSS/JavaScript web-клиент встроен в Go-сервер через `go:embed`
- Docker / Docker Compose

## Архитектура

Backend построен по трёхслойной архитектуре:

1. **Handler (Presentation)** — принимает HTTP-запрос, декодирует входные данные, вызывает сервис и формирует HTTP-ответ.
2. **Service (Business)** — содержит бизнес-правила и сценарии предметной области.
3. **Repository (Data Access)** — инкапсулирует SQL и работу с PostgreSQL.

Слои связаны через интерфейсы репозиториев. Это позволяет отделить бизнес-логику от конкретной СУБД и упрощает тестирование.

## Основные функции

- регистрация и вход пользователя;
- JWT-аутентификация;
- роли клиента и мастера;
- профиль мастера;
- услуги с ценой и длительностью;
- рабочее расписание;
- формирование свободных слотов;
- создание и отмена записей;
- подтверждение, завершение и отмена записей мастером;
- уведомления пользователя;
- Docker-развёртывание.

## Запуск

Нужны Go и PostgreSQL либо Docker.

Для Docker:

```bash
cd deploy
cp .env.example .env
# заполнить POSTGRES_PASSWORD и JWT_SECRET

docker compose up --build
```

При запуске через Docker Compose миграции выполняются автоматически отдельным контейнером `migrate`. Отдельный бинарник находится в `backend/cmd/migrate`.

API и веб-интерфейс слушают порт `8080` по умолчанию.

После запуска откройте `http://localhost:8080/`.

## Проверка

Логика бронирования покрыта unit-тестами на уровне Service. Для локального запуска тестов нужен установленный Go и доступ к зависимостям из `go.mod`:

```bash
cd backend
go test ./...
```

## Структура слоёв

Для каждого основного модуля применяется одна и та же схема:

```text
Handler -> Service -> Repository -> PostgreSQL
```

Handler не содержит SQL и не обращается к PostgreSQL напрямую. Service содержит бизнес-правила, а Repository инкапсулирует запросы к базе данных.
